## 📋 项目概述

### 背景

CCJK CLI 工具需要一个云端供应商注册表服务，支持用户通过短码快速配置 API 供应商。

**用户场景**:
```bash
# 场景1: 使用已注册供应商
npx ccjk 302
# → 查询云端，返回 302.AI 信息，用户确认后配置

# 场景2: 创建新供应商
npx ccjk myapi
# → 查询云端，未找到，用户填写信息后注册到云端
```

### 核心功能

1. **供应商查询** - 根据短码查询供应商信息
2. **供应商注册** - 用户自助注册新供应商（先到先得）
3. **供应商列表** - 获取可用供应商列表

## 🗄️ 数据库设计

### 表结构: `providers`

```sql
CREATE TABLE providers (
    -- 主键
    id INTEGER PRIMARY KEY AUTOINCREMENT,

    -- 核心字段
    shortcode TEXT NOT NULL UNIQUE,      -- 短码，唯一标识
    name TEXT NOT NULL,                   -- 显示名称
    api_url TEXT NOT NULL,                -- API 基础 URL

    -- 可选字段
    description TEXT,                     -- 描述信息
    models TEXT,                          -- 推荐模型列表 (JSON 数组)

    -- 分类和状态
    category TEXT DEFAULT 'custom',       -- 分类
    status TEXT DEFAULT 'active',         -- 状态
    verified INTEGER DEFAULT 0,           -- 是否官方验证 (0/1)

    -- 元数据
    created_at TEXT DEFAULT (datetime('now')),
    created_by TEXT,                      -- 创建者标识 (IP hash 或用户ID)
    updated_at TEXT DEFAULT (datetime('now')),

    -- 统计 (可选)
    usage_count INTEGER DEFAULT 0,        -- 使用次数

    -- 约束
    CHECK (length(shortcode) >= 2 AND length(shortcode) <= 20),
    CHECK (length(name) >= 1 AND length(name) <= 50),
    CHECK (category IN ('official', 'relay', 'domestic', 'custom')),
    CHECK (status IN ('active', 'maintenance', 'deprecated', 'testing'))
);
```

### 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | INTEGER | 自动 | 自增主键 |
| `shortcode` | TEXT | ✅ | 唯一短码，2-20字符，小写字母/数字/连字符 |
| `name` | TEXT | ✅ | 显示名称，1-50字符 |
| `api_url` | TEXT | ✅ | API 基础 URL，必须是有效的 HTTP/HTTPS URL |
| `description` | TEXT | ❌ | 描述信息，最多 200 字符 |
| `models` | TEXT | ❌ | JSON 数组字符串，如 `["gpt-4", "gpt-3.5"]` |
| `category` | TEXT | ❌ | 分类：official/relay/domestic/custom |
| `status` | TEXT | ❌ | 状态：active/maintenance/deprecated/testing |
| `verified` | INTEGER | ❌ | 是否官方验证：0=否，1=是 |
| `created_at` | TEXT | 自动 | 创建时间 ISO 8601 格式 |
| `created_by` | TEXT | ❌ | 创建者标识 |
| `updated_at` | TEXT | 自动 | 更新时间 |
| `usage_count` | INTEGER | ❌ | 使用统计（可选实现） |

### 索引

```sql
CREATE UNIQUE INDEX idx_providers_shortcode ON providers(shortcode);
CREATE INDEX idx_providers_category ON providers(category);
CREATE INDEX idx_providers_status ON providers(status);
CREATE INDEX idx_providers_verified ON providers(verified);
CREATE INDEX idx_providers_created_at ON providers(created_at);
```

## 🔌 API 接口规范

### 基础信息

| 项目 | 值 |
|------|-----|
| Base URL | `https://api.claudehome.cn/v1` |
| 协议 | HTTPS only |
| 数据格式 | JSON |
| 字符编码 | UTF-8 |

### 通用响应格式

**成功响应**:
```json
{
  "success": true,
  "data": { ... },
  "timestamp": "2026-01-25T10:30:00Z"
}
```

**错误响应**:
```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "Human readable message"
  },
  "timestamp": "2026-01-25T10:30:00Z"
}
```

### 错误码定义

| 错误码 | HTTP 状态码 | 说明 |
|--------|-------------|------|
| `PROVIDER_NOT_FOUND` | 404 | 供应商不存在 |
| `SHORTCODE_EXISTS` | 409 | 短码已被占用 |
| `INVALID_SHORTCODE` | 400 | 短码格式无效 |
| `INVALID_API_URL` | 400 | API URL 格式无效 |
| `INVALID_REQUEST` | 400 | 请求参数无效 |
| `RATE_LIMITED` | 429 | 请求频率超限 |
| `INTERNAL_ERROR` | 500 | 服务器内部错误 |

### API 1: 查询供应商

**请求**:
```
GET /v1/providers/{shortcode}
```

**路径参数**:
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| shortcode | string | ✅ | 供应商短码 |

**成功响应** (200):
```json
{
  "success": true,
  "data": {
    "shortcode": "302",
    "name": "302.AI",
    "apiUrl": "https://api.302.ai",
    "description": "302.AI 中转服务 - 支持多种模型",
    "models": ["gpt-4", "gpt-4-turbo", "gpt-3.5-turbo", "claude-3-opus"],
    "category": "relay",
    "status": "active",
    "verified": true,
    "createdAt": "2024-01-01T00:00:00Z"
  },
  "timestamp": "2026-01-25T10:30:00Z"
}
```

**错误响应** (404):
```json
{
  "success": false,
  "error": {
    "code": "PROVIDER_NOT_FOUND",
    "message": "Provider 'bltcy' not found"
  },
  "timestamp": "2026-01-25T10:30:00Z"
}
```

**实现逻辑**:
```
1. 将 shortcode 转为小写
2. 查询数据库: SELECT * FROM providers WHERE shortcode = ? AND status != 'deprecated'
3. 如果找到，返回数据（字段名转为 camelCase）
4. 如果未找到，返回 404
5. 可选：更新 usage_count
```

### API 2: 创建供应商

**请求**:
```
POST /v1/providers
Content-Type: application/json
```

**请求体**:
```json
{
  "shortcode": "myapi",
  "name": "My API Service",
  "apiUrl": "https://api.myservice.com/v1",
  "description": "我的 API 服务",
  "models": ["model-a", "model-b"]
}
```

**请求字段**:
| 字段 | 类型 | 必填 | 验证规则 |
|------|------|------|----------|
| shortcode | string | ✅ | 2-20字符，`/^[a-z0-9][a-z0-9-]*[a-z0-9]$\|^[a-z0-9]{1,2}$/`，不能是保留词 |
| name | string | ✅ | 1-50字符，不能为空白 |
| apiUrl | string | ✅ | 有效的 HTTP/HTTPS URL |
| description | string | ❌ | 最多 200 字符 |
| models | string[] | ❌ | 数组，最多 20 个元素，每个最多 50 字符 |

**保留短码列表** (禁止注册):
```javascript
const RESERVED_SHORTCODES = [
  // CLI 命令
  'help', 'menu', 'init', 'setup', 'config', 'update', 'doctor',
  'mcp', 'skills', 'agents', 'hooks', 'api', 'cloud', 'system',
  'version', 'test', 'debug', 'serve', 'daemon',
  // 系统保留
  'admin', 'root', 'official', 'ccjk', 'claude', 'anthropic',
  'openai', 'google', 'microsoft', 'meta', 'aws', 'azure',
  // 通用保留
  'null', 'undefined', 'true', 'false', 'new', 'delete'
]
```

**成功响应** (201):
```json
{
  "success": true,
  "data": {
    "shortcode": "myapi",
    "name": "My API Service",
    "apiUrl": "https://api.myservice.com/v1",
    "description": "我的 API 服务",
    "models": ["model-a", "model-b"],
    "category": "custom",
    "status": "active",
    "verified": false,
    "createdAt": "2026-01-25T10:30:00Z"
  },
  "timestamp": "2026-01-25T10:30:00Z"
}
```

**错误响应示例**:

短码已存在 (409):
```json
{
  "success": false,
  "error": {
    "code": "SHORTCODE_EXISTS",
    "message": "Shortcode 'myapi' already exists"
  }
}
```

短码格式无效 (400):
```json
{
  "success": false,
  "error": {
    "code": "INVALID_SHORTCODE",
    "message": "Shortcode must be 2-20 characters, lowercase alphanumeric with hyphens, cannot start/end with hyphen"
  }
}
```

**实现逻辑**:
```
1. 解析请求体 JSON
2. 验证必填字段
3. 验证 shortcode 格式和保留词
4. 验证 apiUrl 格式
5. 检查 shortcode 是否已存在
6. 插入数据库
7. 返回创建的数据
```

**实现建议**: 使用 Cloudflare Rate Limiting 或 KV 存储计数

### 2. 输入验证

```typescript
// 短码验证
function isValidShortcode(shortcode: string): boolean {
  if (!shortcode) return false
  if (shortcode.length < 2 || shortcode.length > 20) return false
  if (!/^[a-z0-9][a-z0-9-]*[a-z0-9]$|^[a-z0-9]{1,2}$/.test(shortcode)) return false
  if (RESERVED_SHORTCODES.includes(shortcode)) return false
  if (/^\d+$/.test(shortcode)) return false // 禁止纯数字
  return true
}

// URL 验证
function isValidApiUrl(url: string): boolean {
  try {
    const parsed = new URL(url)
    if (!['http:', 'https:'].includes(parsed.protocol)) return false
    // 生产环境禁止 localhost
    if (parsed.hostname === 'localhost' || parsed.hostname === '127.0.0.1') return false
    return true
  } catch {
    return false
  }
}

// 文本清理 (防 XSS)
function sanitizeText(text: string): string {
  return text
    .replace(/[<>]/g, '') // 移除 HTML 标签字符
    .trim()
    .slice(0, 200) // 限制长度
}
```

## 🚀 部署指南

### Cloudflare Workers 部署

**1. 项目初始化**:
```bash
# 创建项目
npm create cloudflare@latest ccjk-provider-api
cd ccjk-provider-api

# 安装依赖
npm install hono
```

**2. 创建 D1 数据库**:
```bash
# 创建数据库
npx wrangler d1 create ccjk-providers

# 记录返回的 database_id
```

**3. 配置 wrangler.toml**:
```toml
name = "ccjk-provider-api"
main = "src/index.ts"
compatibility_date = "2024-01-01"

[[d1_databases]]
binding = "DB"
database_name = "ccjk-providers"
database_id = "your-database-id-here"

[vars]
ENVIRONMENT = "production"
```

**4. 初始化数据库**:
```bash
# 创建 schema.sql 文件（包含上面的建表语句和初始数据）
npx wrangler d1 execute ccjk-providers --file=./schema.sql
```

**5. 部署**:
```bash
npx wrangler deploy
```

**6. 自定义域名**:
- 在 Cloudflare Dashboard → Workers → 你的 Worker → Triggers
- 添加自定义域名: `api.claudehome.cn`

## 🧪 测试用例

### 单元测试

```typescript
describe('Provider API', () => {
  describe('GET /providers/:shortcode', () => {
    it('should return provider for valid shortcode', async () => {
      const res = await fetch('/v1/providers/302')
      expect(res.status).toBe(200)
      const data = await res.json()
      expect(data.success).toBe(true)
      expect(data.data.shortcode).toBe('302')
    })

    it('should return 404 for unknown shortcode', async () => {
      const res = await fetch('/v1/providers/unknown123')
      expect(res.status).toBe(404)
      const data = await res.json()
      expect(data.error.code).toBe('PROVIDER_NOT_FOUND')
    })
  })

  describe('POST /providers', () => {
    it('should create provider with valid data', async () => {
      const res = await fetch('/v1/providers', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          shortcode: 'testapi',
          name: 'Test API',
          apiUrl: 'https://api.test.com/v1'
        })
      })
      expect(res.status).toBe(201)
    })

    it('should reject invalid shortcode', async () => {
      const res = await fetch('/v1/providers', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          shortcode: 'a', // 太短
          name: 'Test',
          apiUrl: 'https://api.test.com'
        })
      })
      expect(res.status).toBe(400)
    })

    it('should reject reserved shortcode', async () => {
      const res = await fetch('/v1/providers', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          shortcode: 'help',
          name: 'Test',
          apiUrl: 'https://api.test.com'
        })
      })
      expect(res.status).toBe(400)
    })

    it('should reject duplicate shortcode', async () => {
      const res = await fetch('/v1/providers', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          shortcode: '302', // 已存在
          name: 'Test',
          apiUrl: 'https://api.test.com'
        })
      })
      expect(res.status).toBe(409)
    })
  })
})
```
